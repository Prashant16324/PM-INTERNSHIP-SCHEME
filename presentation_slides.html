Concurrency Architecture

Concurrency-Safe Smart Allocation

Pessimistic Row-Level Locking Prevents Seat Over-Allocation

ACID Transaction with Row Locking

When the allocation routine processes an internship, it executes:

internship = db.query(Internship)
  .filter(Internship.id == app.internship_id)
  .with_for_update().first()

Guarantees no concurrent admin run or user cancellation can induce race conditions.

Duplicate Allocation Guard

  • In-memory set tracks allocated candidates across each round.
  • Enforces compound database constraint (uq_student_internship_app).
  • Automatic seat restoration upon administrative cancellation.

Database Engineering

Relational Schema & 3NF Proof

11 Normalized Tables with Complete Referential Integrity

1NF: Atomic Values

All multi-valued attributes (skills, locations) are separated into individual normalized tables or structured JSON arrays.

2NF: Full Functional Dependency

Composite unique constraints ensure every non-key column strictly depends on the entire primary key.

3NF: Zero Transitive Dependency

Company details reside strictly in `companies`; internships store only foreign key references (`company_id`).
